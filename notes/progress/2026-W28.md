## 25. Delegated runtime events

Completed Slice 6D-D.

Parser, component graph, template graph, and manifest event semantics now preserve explicit event types. JSX `onClick` becomes compiler-owned event type `click`, and manifest event records now include:

- template node ID
- event type
- handler reference

Template HTML now emits event-specific marker attributes such as `data-ez-on-click`.

The runtime no longer installs per-element click listeners. It builds an event index by event type and template node ID, installs one delegated document listener per event type, walks from the browser event target up through `data-ez-node` ancestors, and dispatches through the manifest action index.

The double-binding browser probe now exercises a nested click target inside one button and a second button wired to a separate handler. Both route through delegated click dispatch and update the subscribed bindings.

Added compiler diagnostics for unsupported event types and duplicate event declarations on the same element.

Current limitation: only delegated `click` is supported; event modifiers and richer propagation semantics are still deferred.

## 40. Dynamic attribute bindings

Completed Slice 7B.

Supported JSX expression attributes of the form:

```tsx
<button disabled={this.disabled} title={this.label}>
```

The compiler now lowers supported state-backed expression attributes into template binding nodes with stable IDs, initial primitive state values, and manifest metadata identifying the binding target:

```json
{ "kind": "binding", "target": "attribute", "attribute": "disabled" }
```

Static HTML generation applies the initial binding value. Boolean attributes such as `disabled` are omitted when false and emitted as presence attributes when true; string attributes render escaped initial text.

The browser runtime skips comment-anchor validation for attribute binding nodes and registers binding callbacks against the existing component state store. Updates apply in place to the already-rendered element:

- boolean attributes toggle attribute presence
- property-backed attributes such as `disabled` also update the DOM property

## 43. Conditional rendering

Completed Slice 7E.

Conditional rendering now flows through the parser, component graph, template graph, static HTML, manifest, and browser runtime.

Supported forms:

```tsx
{this.enabled ? <span>On</span> : <span>Off</span>}
{this.enabled && <span>On</span>}
```

The compiler now emits a conditional template child with:

- a conditional node ID
- stable start/end boundary IDs
- the `this.<stateField>` condition expression
- serializable initial condition value
- true and false branch template children

Static HTML renders the initial branch from state and wraps it in `ez-conditional-start` / `ez-conditional-end` comments. Runtime manifests serialize a conditional node with branch HTML snippets. ## 46. Keyed list reconciliation

Completed Slice 7F-C.

List templates now emit compiler-owned DOM range anchors:

```html
<!-- ez-list-start:n5:this.labels -->
<li data-ez-node="n7:North">...</li>
<!-- ez-list-end:n6 -->
```

The template manifest records each list's iterable, initial array, item/index variables, key expression, start/end IDs, item-root template ID, and placeholder HTML for inserting a new item root. Static instances use a deterministic `templateNodeId:key` DOM ID, so the runtime can build its initial key-to-element map from the rendered page.

When a recognized array assignment changes the list state, the browser runtime reconciles the list range by:

- retaining existing roots for unchanged keys
- inserting roots for new keys from the compiler-provided template
- moving retained roots into the new key order with `insertBefore`
- removing roots for keys absent from the new array

Added `fixtures/0021-keyed-list-reconciliation` and browser coverage that begins with `North` and `South`, reorders them while inserting `East`, then trims to `East` alone. The probe verifies that moved `North` and `South` roots retain object identity, `East` is inserted, stale roots are removed, and `East` remains the same DOM element through deletion of the other items.
