## JSON fixture comparison policy

Changed the JSON fixture assertion to compare parsed JSON values instead of raw strings.

Reason:

- editor formatting should not break machine-readable fixture tests
- JSON explain output is a structured data contract
- text explain output remains an exact string contract

Added `serde_json` as a dev-dependency for semantic fixture comparison.


## Core module split

Split `ezc_core` into focused modules:

- `model.rs` for data structures
- `summarize.rs` for source-summary analysis
- `explain.rs` for text and JSON explain rendering
- `lib.rs` for public module wiring and tests

No behavior changed. Existing text and JSON fixture tests continue to pass.

Reason:

- keep compiler concepts separated
- preserve a clean public API through re-exports
- prepare for parser-backend spike without growing `lib.rs`


## CLI explain integration tests

Added integration tests for the `ezc_cli explain` command.

The tests run the compiled CLI binary and verify:

- text explain output matches the golden fixture exactly
- JSON explain output matches the JSON fixture semantically
- the command exits successfully
- stdout is valid UTF-8

This protects the actual user-facing compiler command, not just the core library functions.


## CLI parser command

Added `ezc_cli parse <file>`.

The command uses `ezc_parser::parse_file` and prints parser-adapter output for:

- diagnostics
- classes
- decorators
- properties
- methods
- JSX roots
- simple bindings

Added CLI integration tests for valid and broken TSX fixtures.

This exposes the new Oxc-backed parser adapter through the user-facing CLI while preserving the older `explain` source-summary command.
