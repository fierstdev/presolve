## 0.2.0-beta.15 route-local runtime publication

The first interactive production site built with beta.14 exposed a
file-route isolation defect: conventional publication selected the requested
route for HTML composition, but retained sibling route roots while deriving
runtime component and resume products. An action on the selected page could
therefore boot another route against targets that were never rendered and
raise `PSR_INVALID_ORDINARY_TARGET`.

File-route assembly now retains only the compiler-planned owner root that
contains the selected route before instance scope, runtime, and resume products
are derived. A regression fixture proves that a selected interactive route
keeps its layout and local instances while excluding a sibling route's
instances, targets, and events. The real presolve.dev application then proved
that its docs publication contains no homepage targets or resume events, its
homepage counter still updates, cross-route navigation remains clean, and the
state-backed mobile menu closes after navigation without a runtime diagnostic.
