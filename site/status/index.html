Current status.

Presolve is under active development. This page separates what exists in the repository from what is still intentionally outside the product contract.

Implemented

Portability core

  • Application Contract 0.1
  • Environment Specification 0.1
  • Deterministic compatibility resolver
  • Symbolic DeploymentPlan
  • Stable EnvironmentId and ProviderId identity
  • Required/preferred feature negotiation
Implemented

Execution + providers

  • WebAssembly Component workloads
  • OCI/container workload path
  • Docker local executor
  • KV + object-storage capability contracts
  • In-memory KV/object providers
  • Redis KV adapter over RESP/TCP
  • Cloudflare Workers KV adapter
Implemented

Developer workflow

  • presolve build
  • presolve inspect source + release views
  • presolve check
  • presolve plan
  • Versioned JSON projections
  • Rust + TypeScript authoring paths
Public proof

Same-release portability

  • One detached .presolved release built once
  • Memory, Redis, and Cloudflare environment resolution
  • Memory and real Redis execution from the same release bytes
  • Optional live Cloudflare Workers KV execution
  • Release digest and archive SHA verification
  • Exact public demo command verified by CI
Inspect the proof
Not a guarantee

Not stable yet

  • Stable CLI compatibility
  • Stable TypeScript SDK compatibility
  • Production-grade cloud provider support
  • Arbitrary OCI workload compatibility
  • Native executable workload class
  • Full deployment lifecycle/control plane
Next

External validation before broader architecture.

The immediate phase is to put the runnable proof in front of platform, runtime, backend, and distributed-systems engineers and collect concrete objections, missing semantics, and real deployment cases.

Control-plane, scheduler, service-mesh, registry, and lifecycle-management work stays deferred until the core portability model survives outside scrutiny.
