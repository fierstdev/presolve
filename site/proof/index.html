Flagship portability proof

One release.
Different environments.

Presolve builds one immutable application release, resolves those exact bytes against different environments, realizes different providers, and verifies that the application identity never changes.

The claim

Build software once. Decide where it runs later.

The proof is intentionally small. It tests Presolve's central architectural invariant directly rather than hiding it inside a larger application.

Reproduce it

One public command.

The command below is the same entry point exercised by Presolve's public CI.

git clone https://github.com/fierstdev/presolve.git
cd presolve
bash ./demo/portability/run.sh
Prerequisites: Rust with the wasm32-wasip2 target, Docker, Bash, and Python 3. The default proof requires no cloud credentials.

Realization

Different provider implementations execute without rebuilding the application.

The credential-free path executes the release through memory and a real Redis process. Cloudflare execution is an explicit opt-in because it requires account credentials.

01Memory

The provider is realized in-process. The release executes successfully without changing its application identity.

02Redis

A pinned Redis container is started and Presolve realizes a networked RESP/TCP provider against the same release.

03Cloudflare

The same release resolves to Workers KV. Passing --cloudflare promotes the plan to live execution with realization-time credentials.

Identity check

The application never changes.

Before any environment is selected, the script records both the canonical Presolve release digest and the encoded archive SHA-256.

After resolution and execution, it computes both values again and fails unless they are identical.

release digest unchanged: yes
archive sha256 unchanged: yes

PASS — one .presolved release, three plans,
two provider realizations, zero application rebuilds.
What this proves

A deliberately narrow result.

Proven

Core invariant

  • Application release identity is independent of environment selection.
  • A detached release can reconstruct the resolver input it needs.
  • Different ProviderIds can satisfy the same provider-neutral KV requirement.
  • The same release bytes execute through in-process and networked provider implementations.
  • Cloud-specific credentials and endpoints remain outside the application release.
Not claimed

Still outside this proof

  • Production readiness or stable public APIs.
  • Every workload or capability can run everywhere.
  • Automatic infrastructure provisioning.
  • A scheduler, service mesh, registry, or hosted control plane.
  • That all providers have identical semantics beyond negotiated contracts.
Inspect it

Do not take the claim on faith.

The proof is meant to be inspected, challenged, and reproduced.
