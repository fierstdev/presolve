Build software once.

Presolve packages an application and its requirements into an immutable release. Environments declare what they can provide. Presolve resolves the two and produces an inspectable deployment plan.

The model

Application requirements stay separate from deployment supply.

The application describes what it needs. The environment describes what exists here. The resolver joins them without putting infrastructure choices into application identity.

Immutable release

The release does not know where it will run.

A .presolved bundle carries application identity, requirements, workload artifact identity, and topology. Environment-specific endpoints, credentials, provider configuration, registry locations, and placement stay outside it.

Implemented today

The proof rests on working architecture, not a mock.

Presolve is pre-stable, but the portability path is implemented and covered by public checkpoints.

01Workloads

WebAssembly Components and OCI/container workload identity and execution paths.

02Capabilities

Versioned KV and object-storage capability contracts with feature negotiation.

03Providers

Memory, Redis, object storage, and a real Cloudflare Workers KV adapter.

04Builds

Deterministic .presolved packaging across Component, OCI, mixed, and TypeScript paths.

05Resolution

Deterministic compatibility checks and inspectable symbolic deployment plans.

06Authoring

Rust and TypeScript paths, with presolve.toml remaining the language-neutral contract.

Scope

Presolve is not a control plane.

The current project stops at deterministic compatibility, immutable application identity, provider selection, and execution/materialization boundaries.

Scheduling, service mesh, fleet management, registries, and full deployment lifecycle management are not being folded into the core before the portability model has external proof.
