Getting started

Run your first Presolve workflow.

This guide uses the repository's KV example to show the complete developer loop. You will build the application once, describe a local environment, check compatibility, inspect the resulting plan, and run the app without learning the full architecture first.

The goal is to make the Presolve workflow concrete before introducing its formal vocabulary. By the end, you should be able to answer three practical questions: what am I shipping, can this environment run it, and what will Presolve use there?

Before you begin

Prerequisites.

Presolve is currently a developer preview and the CLI is built from source. For this walkthrough you need Git and a Rust toolchain with Cargo. The included KV example builds a WebAssembly Component through the repository's current Rust authoring path.

You do not need Redis, PostgreSQL, S3, Cloudflare credentials, or Docker for this first local walkthrough.
Step 1

Build the Presolve CLI.

git clone https://github.com/fierstdev/presolve.git
cd presolve

cargo build -p presolve-cli
export PATH="$PWD/target/debug:$PATH"

presolve --help

The final command should print the Presolve CLI help. Keeping target/debug on your PATH means the rest of the guide can use presolve directly.

What this does not do

Building the CLI does not build an application release and does not create an environment. It only prepares the developer tooling.

Step 2

Open the KV example.

cd examples/kv-demo
ls

The directory contains normal application source plus presolve.toml. That file tells Presolve what the application is and what it requires. For this example, the important requirement is key-value storage.

Application source

The code that implements the example's behavior.

presolve.toml

The portable description of what the application needs to run.

You can inspect the application before any environment exists:

presolve inspect

Use this whenever you want to verify what Presolve understands from the application definition without mixing in deployment choices.

Step 3

Create a local environment.

An application says what it needs. An environment says what is available here. For local development, create an environment beside the example and add an in-memory KV provider:

presolve env init local-dev
presolve env provider add memory-services --provides kv
presolve env show
presolve env check

This creates presolve.env.toml. The generated environment has a stable identity, explicit execution support, resource capacity, and the KV service you just declared.

Why this is separate from the app

The example still asks for key-value storage. It does not need to know that this environment satisfies that need with an in-memory provider. A different environment can satisfy the same requirement with Redis or Cloudflare KV.

presolve env check validates the environment file itself. It does not yet answer whether this particular application can run there. That is the job of presolve check.
Step 4

Build the application once.

presolve build

The current Rust authoring path builds the example Component and packages the application into a .presolved release under dist/.

You should see output identifying both the release path and its digest. Conceptually, this is the thing you ship:

dist/kv-demo.presolved
sha256:…

Presolve does not need the local environment in order to decide what this release is. The build remains separate from environment selection.

Inspect the detached release

presolve inspect dist/kv-demo.presolved

This reads the application definition back from the packaged release. It is useful when the source tree is no longer present or when you want to confirm exactly what was packaged.

Step 5

Ask whether the environment can run it.

presolve check

Presolve compares the application's requirements with the local environment. In this walkthrough, the KV requirement should match the memory-services provider.

A successful result means the environment can satisfy the mandatory requirements represented by the current model. If something is missing, Presolve returns a structured diagnostic instead of silently choosing a weaker fallback.

Try the failure mode

To understand what Presolve is protecting you from, remove the provider, run the check, then add it back:

presolve env provider remove memory-services
presolve check

presolve env provider add memory-services --provides kv
presolve check

The first check should reject the environment because the app still requires KV storage. The second should return to a compatible state.

Step 6

Inspect what Presolve selected.

presolve plan

check answers whether the match is possible. plan shows the actual result of that match: the environment identity, workloads, selected provider identities, versions, and negotiated features.

The app asks for KV.

The application does not name an infrastructure vendor.

02
The environment offers memory KV.

The environment declares concrete supply.

You can inspect the selected provider before runtime materialization.

Machine-readable output

For CI, automation, editors, and higher-level tooling, use the versioned JSON projection:

presolve inspect --json
presolve check --json
presolve plan --json

Do not scrape human output when a machine-readable form is available.

Step 7

Run the app locally.

presolve dev --input "hello"

The local development path resolves the same application/environment boundary, realizes the selected local provider implementation, assembles the runtime, and invokes the Component.

The important separation remains intact: the app asked for KV semantics, the environment supplied a provider, the plan selected it, and only then did the local node materialize the implementation.

The mental model

You now know the core workflow.

Troubleshooting

Common first-run problems.

presolve: command not found

The CLI binary is not on your current shell's path. From the repository root, run export PATH="$PWD/target/debug:$PATH" again, or invoke the binary by its full path.

The WebAssembly target is missing

Install it with rustup target add wasm32-wasip2, then retry presolve build.

No environment is found

Run presolve env init in the example directory or a parent directory. Presolve searches upward for the nearest presolve.env.toml.

presolve check reports a missing capability

The application requires a service the environment does not currently advertise. For this guide, confirm that presolve env provider list contains a provider offering KV.

The environment validates, but the app is still rejected

presolve env check only validates the environment declaration. Use presolve check to evaluate the application against it. A valid environment can still be incompatible with a particular application.
