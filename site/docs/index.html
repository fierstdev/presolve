You do not need to understand Presolve's internal terminology before using it. The shortest path is: install the CLI, run the core commands, then read the deeper reference only when a concept becomes relevant.

Quickstart

Run Presolve from the repository.

git clone https://github.com/fierstdev/presolve.git
cd presolve
cargo build -p presolve-cli
export PATH="$PWD/target/debug:$PATH"

presolve --help

Presolve is still in developer preview, so the current CLI is built from source. Once it is available on your path, the main workflow is deliberately small.

Core workflow

Think in questions, not Presolve vocabulary.

01
presolve inspect — What does Presolve think my app needs?

See the application definition without selecting any infrastructure.

02
presolve build — What exact build am I shipping?

Create a .presolved package that does not contain environment-specific choices.

03
presolve check — Can this environment run it?

Verify compatibility before execution. If it cannot run, Presolve explains what is missing.

04
presolve plan — What will it actually use?

Inspect the runtime and provider selections Presolve made for this environment.

The three files you'll meet

The names are less important than what each one answers.

Your apppresolve.toml

What is this application, and what does it need in order to run?

 A place it can runpresolve.env.toml

What runtimes, services, and resources are available in this environment?

 The thing you shipapplication.presolved

The packaged application produced by presolve build. It stays the same when you evaluate another environment.

 The answerDeployment plan

What Presolve selected when it matched one application build to one environment.

When the docs get technical

Translate the jargon back to these simple ideas.

Technical termPlain meaning
Application Contractthe file describing your app and what it needs
Environment Specificationthe file describing what a target environment can provide
Capabilitya service or behavior your app needs, such as key-value storage or SQL
Providerthe concrete implementation that supplies a capability
Resolutionchecking compatibility and choosing matching providers
DeploymentPlanthe recorded result of those choices
Immutable releasethe same packaged application build, unchanged between environments
