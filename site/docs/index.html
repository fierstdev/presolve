Presolve separates application requirements from environment supply. The CLI then builds, inspects, checks, and resolves that model.

Developer Preview

Build from source

Versioned binaries are not published yet. For now, build the CLI from the repository.

git clone https://github.com/fierstdev/presolve.git
cd presolve
cargo build -p presolve-cli

./target/debug/presolve --help
Presolve is pre-stable. CLI and schema compatibility are not guaranteed yet.
Flagship proof

Reproduce the core portability claim.

The fastest way to evaluate Presolve is to run the same proof used by public CI. It builds one immutable release once, resolves it against memory, Redis, and Cloudflare environments, executes the same release through memory and Redis, and verifies that the application identity did not change.

bash ./demo/portability/run.sh

The default path requires no cloud credentials. See the proof page for the provider matrix, scope, and links to the technical walkthrough.

Application

Declare requirements in presolve.toml.

The Application Contract describes the application without choosing the infrastructure that will satisfy it.

contract_version = "0.1"

[application]
name = "orders"
version = "1.0.0"

[[workloads]]
name = "api"
kind = "component"

[[capabilities]]
interface = "presolve:kv/store"
version = "^0.1"

[resources]
memory_mib = 128
cpu_millis = 250

[network]
outbound = "deny"

Workloads, capability requirements, resource needs, topology, and network policy become part of the application model. Provider credentials and environment-specific endpoints do not.

Environment

Describe available supply in presolve.env.toml.

The Environment Specification says what execution classes, resources, and capability providers are available here.

presolve env init local
presolve env provider add memory-services --provides kv
presolve env check

Providers receive stable ProviderId values. The resolver chooses among declared supply; provider realization details stay outside the Application Contract.

CLI

The current workflow

Inspect source semantics

presolve inspect

Shows Presolve's normalized view of the nearest Application Contract. No environment is required.

Build an immutable release

presolve build
presolve inspect dist/orders.presolved

The .presolved release contains immutable application identity and requirements, not deployment configuration.

Check compatibility

presolve check

Answers whether the nearest environment can satisfy the application and reports stable resolver diagnostics when it cannot.

Inspect the exact plan

presolve plan

Shows the successful symbolic DeploymentPlan: workloads, exact selected providers and versions, negotiated features, and unbound optional capabilities.

Automation

Versioned JSON projections

presolve inspect --json
presolve check --json
presolve plan --json
presolve inspect dist/orders.presolved --json

Machine output uses the explicit presolve.cli schema instead of serializing internal Rust structs directly. Rejected check and plan calls emit structured PS2xxx problems before returning a non-zero status.
