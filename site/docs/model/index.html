Core model

Application, environment, deployment.

Presolve keeps these as separate first-class concepts so application identity does not collapse into one infrastructure choice.

Docs / The model

The central Presolve question is not “which cloud are we deploying to?” It is “what does this application require, what can this environment supply, and can the two be matched without changing the application release?”

The plan is symbolic. The resolver never needs concrete Redis clients, database connections, cloud credentials, or runtime implementation objects.

Three concepts

Do not collapse them together.

01Application

The portable thing being distributed: its requirements, topology, workload identity, and semantic capability needs.

02Environment

A declaration of what one place can execute and supply: resources, workload classes, providers, versions, and features.

03Deployment

The result of resolving one immutable application release against one environment at one point in time.

04Realization

Node-side materialization of the symbolic plan into concrete runtime/provider implementations and realization-time settings.

Boundary

What changes—and what must not.

Application identity may contain
  • capability requirements
  • workload artifact identity
  • minimum resources
  • network policy
  • application topology
Application identity must not contain
  • selected environment ID
  • selected ProviderId
  • cloud credentials or secrets
  • service endpoints
  • database paths or connection strings

This separation is the invariant exercised by every portability proof in the repository.

Resolution

Compatible is a deterministic statement.

A successful resolution means the environment can satisfy every mandatory application requirement represented by the current semantic model. A rejected resolution returns structured problems instead of silently falling back.

Resolved

component execution is available, resource minimums fit, capability versions match, and required semantic features are supported.

Rejected

Examples include unsupported workload classes, insufficient resources, no compatible provider version, or a missing required feature.

Endpoint addresses, credentials, file paths, and similar operational settings are supplied only when the selected provider is realized.

Invariants

The rules Presolve is trying to preserve.

  1. Application identity is independent of deployment environment.
  2. Application, Environment, and Deployment are separate concepts.
  3. Applications request capability semantics, not vendors.
  4. Capability semantics are independent of binding transport.
  5. Resolver output remains symbolic until node materialization.
  6. The runtime executes a resolved plan; it does not own environment resolution.
  7. A .presolved release never encodes environment-specific provider selection.
