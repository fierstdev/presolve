# Contributing to Presolve

Contributions should be small, evidence-backed, and consistent with the frozen
contracts. Before opening a change, read the relevant document in
[`docs/`](docs/README.md), keep generated files and credentials out of Git, and
run only the verification that exercises the changed surface.

Use an issue form for a bug or a bounded proposal. Pull requests should explain
scope, exclusions, verification, and documentation/fixture impact. User-facing
syntax or durable architecture changes need the appropriate RFC or ADR.

## Support boundary

This repository accepts source, documentation, fixture, and reproducibility
reports. It does not provide production hosting, managed services, security
monitoring, deployment support, private support channels, or an SLA.
