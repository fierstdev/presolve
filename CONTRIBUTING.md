# Contributing to Presolve

Contributions should be small, evidence-backed, and consistent with the public
alpha contract. Before opening a change, read the relevant current document in
[`docs/`](docs/README.md), keep generated files and credentials out of Git, and
run the verification that exercises the changed surface.

Use an issue form for a bug or bounded proposal. Pull requests should explain
scope, exclusions, verification, and documentation/fixture impact. Changes to
user-facing syntax, generated artifact compatibility, or durable architecture
need an RFC or ADR before implementation.

## Support boundary

This repository accepts source, documentation, fixture, and reproducibility
reports. It does not provide production hosting, managed services, security
monitoring, deployment support, private support channels, or an SLA.
